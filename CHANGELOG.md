## [Unreleased]

### Security
- Closed Issue #477: bumped the Go toolchain directive from `go1.26.3`/`.2`/`.1` to **`go1.26.4`** across `go.work` and all Go-module `go.mod` files (`cmd/cortex-gateway`, `pkg/sentinel-go`, `services/sentinel-judge`, `services/sentinel-nats-bridge`). This clears two standard-library vulnerabilities that `govulncheck` started flagging on 2026-06-03: **GO-2026-5039** (`net/textproto`, arbitrary inputs in errors without escaping — reachable via `cortex-gateway` `ClaudeProvider.StreamHTTP` → `ReadMIMEHeader`) and **GO-2026-5037** (`crypto/x509`, inefficient candidate hostname parsing). Both are fixed in `go1.26.4`. No functional or dependency changes (x/crypto is already on 0.45 via #386).

### Changed
- Closed Issue #378: degraded agents (bwrap-start failure, missing cgroup, or sandbox-setup error) are now recorded in the daemon `security_runtime_state` with `bwrap_pid = None` and the `/ram/agents/<name>` home fallback, so the Operator Security API no longer loses sight of agents running without full isolation. Added regression tests `degraded_agent_recorded_in_security_runtime_state` (degraded `None` path) and `healthy_agent_records_pid_and_mount_home` (PID + mount contrast) in `services/sentinel-daemon`.
- Closed Issue #463 auth inconsistency in `sentinel-dashboard-backend`: the four projection read routes (`/api/agents`, `/api/rooms`, `/api/metrics`, `/api/tasks`) are now behind `require_auth` (grouped sub-router + `route_layer`), consistent with the control plane — the real sim projection data (agent names/roles/bio-state, rooms, KPIs, tasks) is no longer readable unauthenticated over HTTPS GET (a #431-legacy gap found in the Phase-2 live smoke). `/api/cert-hash` deliberately stays public (the browser needs the cert hash *before* login for WebTransport `serverCertificateHashes` pinning, documented in the route comment); `/api/auth/*` and `/api/wt-ticket` are unchanged. The console is unaffected (it gets agents via the WebTransport push, not these GET routes). The router construction moved into `build_app()` so the auth gates are integration-testable (`tower::ServiceExt::oneshot`: unauth → 401, valid session → reaches the handler, cert-hash → 200 unauth).
- Replaced the historical fixed 60-agent `AgentId` ceiling for Issue #414 with explicit configurable bounds used by Agent TOML loading, daemon dry-run/orchestration, Judge-Alert AgentId parsing, and nightrun loading. The default remains 60 for existing configs, while Gaia-generated companies can validate larger cohorts end to end.
- Superseded Issue #396's DEV-006 WASM-default runtime decision with Issue #407 DEV-007: the Nano-Container platform now uses a runtime-agnostic CRI-style contract with explicit per-workload runtime selection and no global default runtime.
- Hardened Issue #402 dashboard operator auth into a real XSS defense: the operator key is now exchanged once at login (`POST /api/auth/login`, constant-time compare) for a random server-side session token (in-memory `Map<token, expiry>`, 12h TTL, revocable via `POST /api/auth/logout`), delivered as an `httpOnly` + `SameSite=Strict` cookie. The key is never held in JS again; `requireAuth` validates the cookie instead of an `Authorization` header; `api-key.js` was removed and `control/floorplan/timetravel.js` send the cookie via `credentials:'same-origin'`. `DASHBOARD_COOKIE_SECURE=auto|on|off` controls the `Secure` flag (auto detects HTTPS via `X-Forwarded-Proto`). **Residual (documented in `docs/security/threat-model.md`):** key+cookie transit cleartext over plain HTTP on the LAN deploy VM — no regression vs the old Bearer scheme; production belongs behind an HTTPS proxy with `Secure` on. The read-only telemetry WebSocket stays intentionally unauthenticated (no state changes).
- Moved Issue #400 dashboard operator API key out of `sessionStorage` into a shared in-memory module (`dashboard/public/js/api-key.js`), consumed by `control.js`, `floorplan.js`, and `timetravel.js`. This clears the CodeQL `js/clear-text-storage-of-sensitive-data` high alerts and removes the threefold duplication of the `getApiKey`/`authHeaders` helpers. **Honest scope:** this fixes the scanner alert and the duplication — it is **not** real XSS hardening (an in-memory variable is just as readable to same-context XSS as `sessionStorage`); genuine token-theft hardening (keeping the key out of JS-accessible storage via httpOnly cookie / server-side auth) is tracked as a separate follow-up issue. Trade-off: the key no longer survives a full page reload (re-enter once per session).
- Activated Issue #380 eBPF production evidence end to end: daemon/dashboard deploy verified `mode=kernel`, no-CAP `userspace` fallback, TCP request deltas, dashboard eBPF cards without `N/A`, and Deploy-VM overhead of 0.012658% amortized on the i7-3930K VM.
- Finalized Issue #382 NMDA episode-selection policy for hippocampus/nightrun: calibrated threshold `0.25`, shared narrative threshold, max 10 selected episodes, selection-quality payload metrics, and Deploy-VM replay evidence for a `2/3` consolidated Night-Run.
- Moved Issue #278 nightrun/shift evolution LLM calls out of the ECS tick loop into an async background task, with VM evidence for fake-gateway success, gateway-down fail-safe behavior, and redb `EVOLUTION_VERSION` writes.
- Added and optimized Issue #379 live sentinel-fs FUSE/CAS verification paths for storage stats and dedup-hit benchmarking; Deploy-VM evidence shows active FUSE agent homes, 99.22% dedup savings, and same-VM median dedup-hit write p95 improved from 40,411 us to 189 us, while the strict `<100us` target remains unmet on the i7-3930K VM.

- Optimized Issue #277 dashboard WebSocket change detection from five per-view polling queries to one Projection-DB `projection_watermarks` lookup per poll cycle, with idle polling skipped when no WebSocket clients are connected; VM benchmark evidence is captured with `dashboard/scripts/measure-ws-polling.sh`.

Deploy-VM benchmarks on Intel i7-3930K show relative improvements of 26.86% physics, 26.34% perception, 52.57% persist e2e, 86.95% persist write-only, and 17.23% full tick.

- Added Issue #432 event-stream push for the dashboard backend (Epic #436 Phase 2): `sentinel-dashboard-backend` now subscribes to the engine event bus (NATS JetStream `SENTINEL_EVENTS`) and pushes an `agent_live` frame to the WebTransport clients on every agent-relevant engine change — **replacing the old 1s projection poll** (no poll, idle ~0 work). Each WebTransport session subscribes to a `tokio::sync::broadcast` channel after its connect-snapshot and writes each frame as its own uni-stream (`Lagged` → skip, next snapshot is authoritative). The subscriber is a daemon task with reconnect backoff (500ms→30s) and never panics/exits when NATS is down (the connect-snapshot + HTTP keep working). **Scope:** only `agent_live` is pushed — `room_live`/`kpi`/`tasks` have no console consumer yet and belong to the 9-view migration (#433); no frontend change.

### Known limitations at this release
- The docker compose demo intentionally exercises only the deterministic + LLM layers
  (ECS world, bio-engine, gateway pipeline, dashboard). It does **not** exercise
  the kernel-bound sandbox primitives (bwrap, Landlock, cgroups v2, netns, eBPF,
  sentinel-fs FUSE) — those need user namespaces and CAP_BPF / CAP_SYS_ADMIN that
  a plain unprivileged container does not have. The full stack is documented in
  `deploy/systemd/*.service` for VM deployment. See README "What the docker demo
  shows — and what it does not" and [docs/known-limitations.md](docs/known-limitations.md).
- The signed v0.1.0-alpha tag will display "Unverified" in the GitHub UI until the
  maintainer's SSH signing key is registered as a Signing Key on GitHub. The tag
  itself carries a valid Ed25519 signature (verifiable locally with
  `git tag -v v0.1.0-alpha`).
