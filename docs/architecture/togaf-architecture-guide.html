Cluster 00 // Architecture Principles

The System's DNA

The entire stack follows three overarching principles. They are not components but the rationale for why every component looks the way it does — and the benchmark for every future decision. If a design violates P1–P3, it is almost certainly wrong.

P1

Share what's common, individualize the diff

At every layer the common part is held exactly once; only the difference is multiplied. This is the source of the nano-density.

  • → CAS-FUSE: one base runtime, N diff chunks (disk)
  • → ECS: one world state, lean component diffs (memory)
  • → Prompt caching: one prefix, N calls (tokens)
  • → KV-cache sharing + Multi-LoRA: one base model, N adapter diffs (VRAM)
P2

Move references, not bytes

The most expensive operation in modern systems is data movement, not computation (the memory wall). We move information (pointers, hashes, handles), never the data itself.

  • → redb memory-mapped: read = pointer, no syscall
  • → Zenoh SHM: the receiver reads the same RAM
  • → ECS: iterate over slices, change detection instead of data comparison
  • → CAS: share the hash, not the file — dedup is re-pointing

Consequence: pointers are only valid within an address space. That dictates the cluster topology (see Cluster 12).

P3

Thinking is expensive and slow — everything else must be vanishingly cheap

An LLM “thought” takes ~10 seconds, not nanoseconds. That is the one defining constraint — the system is structurally I/O-bound (the C10M pattern: massive concurrency with long wait times).

  • → the optimization target is overhead reduction, not latency: overhead/cycle × cycles/s = agents per core
  • → agents as ECS entities, not threads/processes
  • → async, event-driven: a waiting agent uses 0 CPU
  • → the tick drives the cheap deterministic world; thoughts land as rare events

Good system design shows when every decision follows from a few physical facts rather than from taste. P1–P3 are those facts for Project Sentinel.

Research Sleep Cycle // NMDA-inspired Consolidation SOTA

In the human brain, NMDA receptors in the hippocampus decide which experiences move from short-term into long-term memory. Emotional, repeated, and relevant experiences are strengthened (“long-term potentiation”); irrelevant ones are forgotten. Our system mirrors this mechanism: a score rates each day's episode and decides whether it gets consolidated:

LTM_Score = Relevance × Emotional_Intensity × Repetition_Frequency × (1 / Time_Distance)

Security Model // An Honest Assessment

Rust plus in-binary operation largely eliminates one class of bug: memory corruption (~70% of historical CVEs). That's a strong foundation — but memory safety is not the same as security. Four points that an honest security claim must keep in view:

Prompt injection = the main surfaceAgents are LLMs that process untrusted input (user messages, external data, tool outputs) — the ultimate confused-deputy surface. Rust protects against this not at all. This is the largest and most agent-specific attack surface. The remedy: capability-based per-agent tool permissions, output validation, least privilege — not the programming language.
Compartmentalization over monolith“Everything in one address space” means: one memory bug in any unsafe block or dependency = total compromise. High security demands separation (the seL4 principle), not a monolith. The sandbox boundaries (bwrap/Landlock) are the best security asset — not overhead.
unsafe is realSHM, mmap, io_uring, eBPF, FUSE, ECS internals, and SIMD all need unsafe. Memory safety only holds in the safe subset. Mandatory: a cargo-geiger audit, minimizing unsafe, plus formal verification (Kani) of the critical cores.
A threat model is mandatory“Maximum security” is an empty claim without an explicit threat model. Three attackers to separate: (1) the compromised agent from within, (2) the external attacker, (3) the supply-chain attack via a dependency. None is primarily solved by Rust.

The high-security goal is achievable — but through the whole package (compartmentalization + formal verification + threat model + injection defense), not through the language. “Rust = secure” as the main promise is a trap.

Dedup Pipeline Contract — the Data Plane, Not a Background Job

Every agent write crosses this pipeline, so it scales with the aggregated write bandwidth of the whole simulation. Its architectural contract:

Single memory traversalBoundary detection (FastCDC-class, versioned chunk profiles), BLAKE3 chunk fingerprinting, and the incremental object SHA-256 are fed from one pass over the data — per-byte work is memory-bandwidth-bound, so passes are fused, never stacked.
Copy-after-dedupChunk bytes are copied only for content the store does not already hold. Duplicates cost a hash and a lookup — never an allocation.
Exact RAM existence indexA sharded, exact in-memory membership index accelerates the per-chunk existence check in front of the durable store. The durable store remains the sole authority: misses always verify, all destructive mutations go through one central path, and a durable store generation invalidates the index on restore. An accelerator may never become a second source of truth.
Content-based identityChunk identity is the content fingerprint alone; the chunk profile records boundary provenance. Identical bytes dedup across profile generations automatically, and chunker upgrades ship as new, coexisting profiles — never as a silent boundary change.
Why CAS instead of btrfs reflinks?

btrfs reflinks break on every write — when 15 agents run npm install and then write, the CoW shares are gone instantly. CAS works at the hash level: identical content = one blob, no matter when or by whom it was written.

One block per ECS tick, bump allocation (a single addition instead of malloc). At the end of the tick the entire block is freed. Cache-friendly, fragmentation-free.

ECS components in 64-byte cache lines. All positions in one array, all energy values in another. The CPU prefetcher can read ahead.

Dependency Sovereignty — the OSS Intervention Ladder

A 100% open-source stack means every dependency is modifiable at source level — but a fork is a standing liability (rebase and CVE responsibility), not a free optimization. Interventions therefore follow a cost-aware ladder, and dependency facts are established by reachability analysis of the release binaries, never by raw lockfile counting (dev-, build- and foreign-target dependencies are not runtime surface).

Stage 0 · ConfigureFeature minimization (default-features = false + explicit lists) and duplicate-version consolidation, justified per audit row; a deny-gate keeps new duplicates out of the tree.
Stage 1 · BuildProfile-level optimization across the whole tree (LTO, codegen units, ISA baseline) — optimizing foreign code without touching it.
Stage 2 · PatchSurgical [patch.crates-io] changes, each requiring a measured justification, a registry entry (reason, diff size, upstream PR), and an upstream-first obligation — a merged upstream PR retires the patch. CI verifies registry and patches stay in sync.
Stage 3 · OwnFull in-house implementation, reserved for core-domain hot paths (the chunker is the canonical example) with the project's complete test and benchmark discipline.

Patched or owned code transfers CVE responsibility to us — supply-chain governance (cargo-deny, geiger baseline, SBOM) is part of the contract, not an afterthought.

Agent-operated upgrade loop — understand the delta before updating

Every release-reachable Cargo, Go, and npm dependency has a machine-readable DependencyContract: owning component, release roots, enabled features, APIs in use, unsafe/FFI boundaries, local patches, security and performance invariants, mandatory tests, runtime smokes, and rollback. The same policy-as-code pattern applies to provider and model catalogs. An upgrade agent therefore evaluates more than “old versus new”: it explains the upstream delta against our actual usage contract.

1 · DetectRenovate and advisories create a reproducible candidate; they never promote it directly.
2 · AnalyzeLock/module graph, API/source diff, release notes, CVEs, features, and reachability changes are explained against the contract.
3 · ProveThe agent selects targeted unit, integration, failure, and runtime gates; performance is measured only on the declared target hardware, never on the build server.
4 · AttestCycloneDX SBOM[39], SLSA provenance[38], evidence, and rollback are immutably bound to the release.

Agent-operated means automatically analyzed and evidence-prepared, not blindly auto-merged. Storage, wire, determinism, security, and other critical contracts retain an explicit maintainer gate.

Efficiency doctrine: resources per unit of work, not raw throughput

Anyone can be fast on 96 cores. This platform is designed to be impressive on a 15-year-old six-core with 8 GB — which is only possible if efficiency, not hardware, does the work. Consequently, performance is judged on co-primary metrics: throughput and tail latency (p99) together with CPU-seconds per GB, syscalls per operation, and RAM per agent. An optimization that wins one axis by losing another does not win. Optimization decisions carry pre-committed adopt/reject rules, are measured against a recorded baseline on target-class hardware, and an evidence-based rejection is a first-class outcome.

BPF Map Strategy

Per-CPU hash maps

Each CPU has its own map copy → no locking. With 12 threads and N agents: 12 × N × 24 bytes per map. At 50 agents ≈ 15 KB.

Ring buffer (256 KB)

Asynchronous events at a variable rate. One shared buffer instead of per-CPU (since kernel 5.8). On overflow: events dropped, drop counter.

Polling interval

1s for hash maps (enough for the dashboard). Ring buffer event-driven via epoll — no polling.

BTF/CO-RE portability

Programs are compiled with BTF (BPF Type Format). The kernel supplies struct layouts via /sys/kernel/btf/vmlinux. CO-RE (compile once, run everywhere): compile on the build host, load on a VM with a different kernel. Kernel 6.17 has full BTF. For VMs without BTF: automatic fallback to userspace monitoring.

In plain terms Like snapshots on a virtual machine. You can roll the entire simulation back to an earlier point at any time — all agents, all bio values, all rooms, everything. Without having to restart the simulation.
Pointer-based restore SOTA

Events are immutable (append-only). A restore changes no events — only the pointers (projection offsets, active snapshot) are set to an earlier state. Low I/O, low latency, no replay needed.

Hot-Swap Restore (in the running daemon)

No daemon restart. The simulation is rolled back to a snapshot point while running:

1.Pause the tick loop
2.Create a pre-restore snapshot (rollback point)
3.Load the snapshot + deserialize bincode
4.redb restore_all_tables() — all 11 tables in ONE atomic write transaction
5.ECS world restore_ecs_state() — despawn entities + spawn from the snapshot
6.Terminate agent sandbox processes (SIGTERM) + respawn them in fresh bwrap+Landlock sandboxes
7.Projection seeding: fill projection tables directly from the snapshot (NOT event replay!). Set the offset to max(event_id)
8.NATS: broadcast a SnapshotRestored event → consumer reset
9.Dashboard: WebSocket snapshot_restored event → cache invalidation + full reload
10.Resume the tick loop from snapshot.tick + 1

Downtime (hot-swap)

Why projection seeding instead of event replay: events are immutable. Replaying from snapshot.last_event_id would replay all events up to the present state — exactly the state we do NOT want. Instead: fill the projection directly from the snapshot data, set the offset to max(event_id) → old events are skipped.

Arbitrary-Point-in-Time Restore v23 target

The restore above jumps to stored snapshot points. The goal is the slider on any moment AND any event of the first hour (e.g. “when agent X created the file”), coarser after that — matching the tiered retention.

Mechanics: the nearest anchor snapshot ≤ target + a bounded deterministic re-play of (anchor, target], addressed via events.id (intra-tick ordering). Distinction from “no replay” above: that means replay up to now — a bounded re-play up to a target is allowed and is exactly the lever. It builds on the determinism profile (Cluster 12) and runs as a FencedStateTransfer scope=world.

Two accompanying mechanics: when jumping back, the discarded future is marked overwritable (restore_generation/epoch — the pruner clears it in the normal window). And CAS blocks referenced by a retained snapshot are pinned so the trash GC does not delete them — an old restore always finds its files.

Empirically validated (spike #490, measured): bounded same-machine re-play is byte-identical to the live run through 10,000 ticks (in- and cross-process) whenever the anchor snapshot captures the complete state; every observed divergence traced to enumerated snapshot-coverage gaps (AutonomyCooldown/Smells/Chat/Gaia/Broadcast buffers), not engine nondeterminism. Verdict: GO, conditional on closing those gaps — see docs/spikes/SPIKE-490-exact-replay.md.

If any arbitrary single node must be able to continue the whole system alone, every required RecoveryPoint/log/ref must be present on every such node (effectively RF=N for that critical set). A complete binary stack alone is not HA.

Single survivor requires proven isolation

After quorum loss, a remaining node may issue new authority only if it (1) possesses the last required RecoveryPoint and (2) proves the absence of old writers through independent hardware fencing — for example BMC/Redfish power state[33] plus a durable fence receipt. Without that proof, the control plane remains fail-closed; a membership timeout or “peer unreachable” is never sufficient.

“No functional loss” applies only to explicitly Hot+Replicated classes: after failure, functions and already accepted work survive; throughput, parallelism, and if necessary the rate of logical 1 Hz time may fall. External side effects are authorized exactly once through outbox, idempotency, and OwnerTerm.

ReplicaGroups and tick continuity

We replicate information, not transient cache contents: deterministic inputs/event tails, OwnerTerms, RecoveryPoints, queue/outbox positions, and CAS references. One primary tick executor owns side-effect authority; hot replicas hold the declared tick/commit boundary, while warm replicas catch up from checkpoint + event tail. Under resource loss, the load governor reduces parallelism and simulated-time speed in a controlled way — systems and security boundaries are never disabled.

Topology-aware execution: cluster → NUMA → cache

Placement does not end at which node? The scheduler decides hierarchically: (1) cluster by interaction graph, durability, and resources; (2) node by NUMA proximity, CPU/memory pressure, and I/O locality; (3) hot path by worker affinity, per-core queues, prewarm, and cache working set. cgroups v2[34] and NUMA policy[35] form the portable baseline. resctrl for cache/memory-bandwidth classes[36] and sched_ext/eBPF policies[37] remain optional, capability-gated, and immediately reversible optimizations.

L1/L2/L3 contents are not a durability layer and are never transferred. The work description, state references, and priority move; cache heat is rebuilt locally through deterministic prewarm. Every optimization must improve CPU-s/workload, cache misses, tail latency, and fairness without weakening determinism or isolation.

Live Migration = Fenced State Transfer

K8s cannot live-snapshot/migrate pods — for us, snapshot/restore is a core primitive. The key: time travel (Time Machine) and space travel (migration) are the same primitive — an atomic, fenced state transfer.

FencedStateTransfer { scope, owner_epoch, cas_manifest, route_update } with scope=world (rewinding) or scope=nano_container (relocation); phases prepare→validate→fence→commit→postcommit. Per-container fencing instead of globally halting the simulation. “Milliseconds” applies to the lightweight class (ECS-native, small state, pre-warmed target, CAS blocks local/pullable); heavier runtimes are proportionally more expensive — honestly, no blanket promise.

Soft affinity: the nano-container is the unit, not the company

The distributable unit is the nano-container, not the company — the company is a logical umbrella + an affinity signal. Affinity is a soft, dynamic scheduler hint (a cost function), not a hard boundary: a Control Center moves containers live based on two inputs — who works with whom (interaction graph) and node load. A large company may span multiple nodes; the split forms automatically along weak coupling. “Multiple nodes” = primarily VMs/rack, geo is a special case. Heavily communicating containers stay together — unless the node would otherwise become unstable (splitting only pays off when the load savings > the communication cost).

Hierarchy = coordination AND cost topology

A company hierarchy is a proven distributed coordination algorithm: span of control = fan-out limit (10,000 agents → ~5 levels, O(log N) instead of O(N²)). The management layer = context compression (constant prompt size per agent). The coffee kitchen (HallwayEncounter) is the gossip protocol cutting across the hierarchy.

And at the same time the inference-cost axis: C-level → Opus; routine clerks → a local small model. The span-of-control pyramid is the model-tier pyramid — a few expensive heads at the top, many cheap hands at the bottom.

Inference scaling is a prerequisite, not a cost option

Once you solve runtime density (nano-containers), inference immediately becomes the scaling limit: 10,000 agents = 10,000 permanent LLM contexts. KV-cache prefix sharing, multi-LoRA, and BitNet (today an “optional cost layer”) thereby become a scaling prerequisite. The hypervisor and the inference engine are the same scaling problem from two directions — a mirror image of P1 (in-VRAM instead of in-memory).

Built-in distributed CAS — only hashes travel

No external store (with 1–2 VMs, a new weak point). The local CAS stores logically form one content-addressed space: the hypervisor knows the block map (hash→node) and fetches missing blocks peer-to-peer (pull-by-hash) — once per block per node, then cached locally. A sharpening of P2 “move references, not bytes”: only content hashes are valid cluster-wide, in-memory pointers only locally. On relocation, a small state snapshot + hash references travel, never the large data. Native for ECS-native; bwrap/microVM reach it via a CAS manifest instead of file bytes.

The Control Center — placement by graph & load

Places and rebalances nano-containers by two measured signals: the interaction graph (EWMA — who communicates how much with whom) and node load (CPU/mem/IO pressure, CAS miss rate). Because moving is cheap (only pointers), the scheduler optimizes continuously rather than only in an emergency — that is the fluidity K8s lacks. Anti-thrashing against back-and-forth: hysteresis, cooldown/min-residency, a migration budget per window. Cut-cost rule: never split tightly coupled containers, unless the node becomes unstable.

Transport profiles per traffic class

Node-to-node QUIC carries three traffic classes with conflicting needs — small latency-critical control RPCs, bulk block-pull, and snapshot streaming. Each class runs under its own named transport profile (congestion control, flow-control windows sized from measured path properties, per-connection memory bound). The invariant: the data plane may never alter the control plane's resource contract — bulk windows and congestion tuning must not degrade control-RPC latency or fairness. Conservative congestion defaults; experimental algorithms only behind soak/failure hardening evidence.

Release engineering as an architecture contract

One identical, provenance-bound binary for every node (binary parity): the codegen configuration — LTO shape, codegen units, ISA baseline — is part of the determinism profile, chosen by measured evidence with pre-committed decision rules, and recorded in release provenance/SBOM. The ISA baseline is a product decision about the supported platform class (adopted only after validation on the lowest supported class); newer CPUs are exploited via runtime dispatch inside the one binary, never via per-node builds. Any codegen change requires re-validating bit-exact replay before rollout.

Determinism — the homogeneous profile: “same CPU architecture” is not enough — transcendental float functions (exp/sin/ln) are not guaranteed bit-identical even within one ISA (platform, compiler, version).
