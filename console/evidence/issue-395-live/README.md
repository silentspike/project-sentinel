# Issue 395 token-free UI and runtime evidence

Issue #395 was deployed and accepted on its authorized single-node target from
verified merge `bc5b0370611ee5a64cd83e2d41655eff3ffbc546`. The active provider was
the deterministic in-process `local-loop`; no external provider was contacted
and the measured cost was USD 0.

## Runtime acceptance summary

- All 60 agent configurations matched the approved 3/29/28 matrix and matrix
  SHA-256 `a297f22b7c9c32fee18a9f450f12cf52ccef97bd2fcb68e68401b35ea76f6cb5`.
- The deployed catalog matched file SHA-256
  `1138e60eaee2fb022394de46c3b49e8c43c509f3d69645c65357f2c82d7a78da`
  and semantic digest
  `10ed8408bd69c9b10acda44f4cebc889680435945b08a5c3ef2cf068a58680aa`.
- Authenticated Tier 1/2/3 requests resolved to `local-loop-tier1`,
  `local-loop-tier2`, and `local-loop-tier3`, respectively, with
  `cost_source=non_provider_zero` and zero cost.
- The caller-role matrix returned 401 without authentication, 403 for a valid
  but unauthorized role, and 200 for each allowed route/role combination.
  Public compatibility traffic did not expose authoritative hierarchy fields.
- At the recorded acceptance boundary, every checked v2 usage event had a valid
  hierarchy tier, cost source, effective model, and non-negative finite cost.
  Both projection offsets reached the event boundary and hierarchy aggregate
  counts exactly equaled attributed v2 coverage.
- A controlled producer rollback emitted v1 events and zero v2 events, then the
  re-cutover resumed v2 production only after both projection offsets caught up.
- Failure injection proved one provider completion, a failed first local usage
  append, process restart, one persisted usage event, one action event, and no
  remaining full completion row for the stable request ID.
- The final runtime health readback reported 26 expected, runtime, and projected
  agents, zero drift, zero stale entries, zero orphan cgroups, zero zombie PIDs,
  zero worker restarts, and advancing ticks.
- Exact configured secret values were checked internally against service logs
  and diagnostic APIs; zero matches were found. No secret or derived verifier is
  stored in this evidence.

## Single-node routing benchmarks

The exact deployed Go benchmark binary was run on the authorized runtime target
with `-test.run=^$`, a 2-second benchmark duration, five samples per operation,
and `-test.benchmem`. `vmstat`, `iostat`, and per-CPU `mpstat` sidecars captured
load; their output is context only and is not used as release-performance proof.
There were no failures or retries in the accepted run.

An earlier standalone invocation used the wrong working directory, so
relative-path golden tests could not find their fixtures. It was discarded and
is not benchmark evidence. The accepted invocation staged the exact catalog and
wire golden beneath the package-relative repository layout and ended with
`PASS`.
