#529 — LIVE evidence: snapshot-on-shift fires on a real daemon at every shift tick

Setup: an isolated ad-hoc sentinel-daemon (own DB/port :18084, time_scale=600 to force
shifts in seconds, gateway/judge off = 0 tokens) built from the rebased #529 branch (which
includes #530's anchor-delta fix). At time_scale=600 the shift trigger is
detect_shift_from_sim_hour (deterministic), so shifts fire every ~60 ticks.

Observed (daemon log, ANSI-stripped): every "Schichtwechsel abgeschlossen" is immediately
followed by "World Snapshot erstellt" at the SAME tick — i.e. the #529
`SnapshotManager::mark_shift_snapshot_pending()` hook fires the post-shift anchor at the shift
tick, in the real orchestrator tick loop:

NOTE on scope of this live run: the ad-hoc test agents did not load (active=0; the agent

snapshot-on-shift HOOK firing is independent of agent count and is what this run confirms

is proven deterministically by the in-process integration test
`replay::tests::within_shift_replay_from_post_shift_anchor_is_exact` (and the anchor-selection
unit tests). A full live cross-shift restore with a non-trivial agent population was NOT run
on the deploy VM: a second full daemon there is unsafe — the #279 periodic runtime-reconcile
scans the system cgroup tree and treats the *production* daemon's agent cgroups as orphans
(they are not in the ad-hoc roster), attempting to kill them (the attempts failed — no
permission — and production stayed healthy, tick advancing). That live confirmation with real
agents belongs to the main-session production step (real agents + a real wall-clock shift
boundary, non-disruptive).
